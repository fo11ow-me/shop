# Agent Team 协作指南

## 团队成员

| Agent | 角色文件 | 负责模块 | 角色 |
|-------|---------|---------|------|
| Agent T | `test-engineer.md` | 全系统测试 | 测试工程师 |
| Agent A | `admin-developer.md` | mall-admin (管理后台前端) | 开发工程师 |
| Agent B | `portal-developer.md` | mall-portal (用户门户前端) | 开发工程师 |
| Agent C | `server-developer.md` | mall-server (后端服务) | 开发工程师 |

```
              │   发现 Bug？          │
              └──────┬──────────────┘

         ▼                       ▼
┌─────────────────┐    ┌─────────────────┐

│              对应开发 Agent 立即修复                        │

│ 标记全部通过      │    │ 继续下一用例      │
└─────────────────┘    └─────────────────┘
```

## 发起测试-修复循环

使用以下指令启动 Agent T 进行系统测试:

```
Agent T: 读取 .claude/agents/test-engineer.md，按照 docs/test.md 从 P0 开始执行系统测试。
发现问题记录到 docs/bugs.md，定位根因后通知对应开发 Agent 修复，修复完成后回归验证。
```

当测试完成一轮后，可以用:

```
Agent T: 继续执行 P1 测试用例
```

## 并行开发模式（原有）

使用 `superpowers:dispatching-parallel-agents` 技能，一次分发给三个开发 Agent：

```
/dispatching-parallel-agents

Agent A: 读取 .claude/agents/admin-developer.md，负责 mall-admin 模块，执行 [具体任务]
Agent B: 读取 .claude/agents/portal-developer.md，负责 mall-portal 模块，执行 [具体任务]
Agent C: 读取 .claude/agents/server-developer.md，负责 mall-server 模块，执行 [具体任务]
```

## API 接口变更流程

```
1. Agent C 在 server-developer 中修改 API
2. Agent C 同步更新 controller 上的 springdoc 注解
3. Agent C 通知（或 commit message 标注）接口变更
4. Agent A / Agent B 按 springdoc 文档调整前端对接代码
5. Agent T 对变更接口进行回归测试
```

## 协作原则

- **各守边界**: 每个开发 Agent 只修改自己负责的模块目录
- **测试先行**: 发现 Bug 后先记录再修复，修复后必须回归验证
- **Agent T 中立**: 测试工程师不修改业务代码，只记录问题
- **契约先行**: API 变更必须有 springdoc 文档同步
- **独立并行**: 各模块可独立启动开发服务器，不互相阻塞
- **即时修复**: Bug 发现后立即修复，不积压
- **提交隔离**: 建议每个 Agent 在独立分支工作，通过 merge 集成
